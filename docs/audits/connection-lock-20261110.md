# Загрузка игровых данных и сохранение перевода — 2026-11-10

Клиент 1.0.13082, Steam build 26443971. Диагностика началась по сообщению `Could not load game data` на 41% загрузки. В журнале клиента за 9 ноября обнаружены успешное получение архива и затем `IOException: Sharing violation` для `prod/cache/GameData.db`. Windows Restart Manager показал, что файл удерживал запущенный интерактивный патчер. База и архив проходили проверки целостности.

Причина в патчере: Microsoft.Data.Sqlite по умолчанию сохраняет соединения в пуле. В старом патчере после завершения пункта 5 меню и во время ожидания Enter эксклюзивное открытие `GameData.db` и `ru-RU.bytes` возвращало Windows error 32. Отключение пула во всех четырёх местах создания SQLite-соединений освобождает файлы при завершении операций. На работающем окне исправленного патчера оба файла открывались эксклюзивно после проверки; после установки это также проверено на тестовых и настоящих файлах. Справочник: https://learn.microsoft.com/en-us/dotnet/standard/data/sqlite/connection-strings#pooling.

Выяснилась отдельная причина возврата английского текста: клиент всегда распаковывает кешированный `GameData.db.zip`, даже после HTTP 304. Это подтверждается анализом `DataDownloader.DownloadAsync` и запуском клиента: старая переведённая база заменилась английской. Теперь патчер обрабатывает отдельную копию БД из ZIP, сохраняет резервную копию оригинального архива, обновляет ZIP через временный файл и оставляет серверный ETag без изменений. Неповреждённые другие записи ZIP сохраняются. При следующем обновлении сервера может потребоваться повторная установка перевода.

Проверка на изолированных данных: `--check` не изменяет архив; установка переводит записи в БД и ZIP, сохраняет вторую запись ZIP, корректный CRC, исходный ZIP в резервной копии и ETag; повторный `--check` не видит новых изменений. Были проверены запущенный интерактивный патчер до и после исправления и возможность эксклюзивно открыть обе базы.

Во время раннего испытания тестовой сборки был непреднамеренно найден и настоящий игровой кэш, для которого созданы резервные копии `20261110-004215`. Установка сообщила о нуле обновлённых строк; SHA-256 `GameData.db` и `ru-RU.bytes` совпал с их копиями из этого набора. Последующий изолированный ZIP-тест обнаружение реальных кэшей отключал.

После того как пользователь закрыл игру, исправленный патчер применён к Steam и общему кэшу. Проверено, что ZIP содержит переведённую БД, проходит CRC/SQLite quick_check, а исходный ZIP сохранён в `.rus_patch_backups/20261110-005134/`. После запуска из Steam сервер ответил 304, загрузка Static Data и Game Initialize завершилась успешно, а строки «Яд», «Шанс крита» и Уменьшатора остались на русском в извлечённой базе. Скриншот интерфейса не проверялся.

Собраны локальные EXE `dist/fix-sharing-20261110/TheBazaarRusPatcher-Steam.exe` и `...-Tempo.exe`; на момент сборки их SHA-256 `c8183437d353a79969e19fdd876a2d70b58fa569eebadc1e4a31553eec81cd2e`, встроенный перевод содержит 17 643 ключа. Релиз не публиковался.
